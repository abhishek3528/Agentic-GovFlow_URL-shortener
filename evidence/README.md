# Evidence

Everything under this directory is **emitted by scenario code and never written
by hand.** Nothing here is a screenshot, a transcript, or a note someone typed
up after the fact. A bundle that no code path produces would read as fabricated
evidence and would discredit every other claim in this repository, so the rule
is absolute: if it cannot be regenerated by re-running, it is not evidence.

Regenerate the whole set at any time:

```powershell
.venv\Scripts\python.exe -m scenarios.cli run all
```

The directory is git-ignored precisely because it must always be reproducible
from that command rather than carried along as committed state.

## Bundles

One directory per scenario, each named for its run:

| Bundle | Scenario | Terminal state |
|---|---|---|
| `s-01-greenfield/` | Build the baseline URL shortener | `succeeded` |
| `s-02-brownfield/` | Reliability change on the S-01 codebase | `safe_stopped` |
| `s-03-ambiguous/` | Ambiguous analytics change with a governed re-plan | `succeeded` |

`s-02` ending in `safe_stopped` is the intended outcome, not a failure: its
injected persistent fault exhausts its retry budget, compensation runs, and the
run stops without claiming success.

## Files in each bundle

Start at `index.json`. It lists every other file with a content hash.

| File | What it holds |
|---|---|
| `index.json` | Bundle manifest and content hashes - the entry point |
| `result.json` | Terminal run state, reason, and the run's limitations |
| `events.jsonl` | The append-only event stream, one JSON object per line, with a contiguous per-run `seq` |
| `context_versions.json` | Each requirement version, its ambiguities and assumptions, and what it supersedes |
| `plans.json` | Every plan revision, retained rather than overwritten when a re-plan occurs |
| `graph.json` | Task nodes, dependency edges, and artifact producer/consumer flows per revision |
| `artifacts.json` | Produced artifacts with version, lineage, content hash, and stale marker |
| `decisions.json` | Recorded engineering decisions with actor attribution |
| `controls.json` | Gate results, policy decisions (both allows and denies), and approvals |
| `metrics.json` | Reliability metrics, projected from `events.jsonl` alone |

`events.jsonl` is the source of record. Every other file except the raw plan and
context history is a projection over it - metrics in particular are recomputed
from the stream rather than tallied alongside it, which is checked by
`tests/test_governance_negative.py::test_metrics_are_reproducible_from_the_event_stream_alone`.
